# Remaining real-client acceptance

All tests below are **not executed**. They require two dedicated test boxes and a validated live adapter. Do not run them against an existing personal PXG session. Transport-only results do not satisfy these acceptance procedures, and synthetic screenshots are not substitutes.

1. Record the two box names, client hashes, PIDs, process creation times and authorized windows. Check effective filesystem rules, inherited templates and child-process restrictions. Put harmless sentinel files in permitted test roots and another box's test root. Through every reachable open/save/export dialog, URI handler and child process, verify that only the authorized files are accessible. Keep required dialogs open and functional. Do not enable remote access if this fails.
2. Use two physical client devices, with synchronized recording of both viewers and the local game windows. Start a third recording of the administrator's physical input. A and B hold W together for three seconds; A releases while B holds for three more. Repeat with Ctrl/Shift held on A while B types, clicks and uses hotkeys. A drags an item while B moves its own cursor. The administrator types/clicks in an unrelated app throughout. Verify resulting movement, text, modifiers, item position and lack of host cursor movement.
3. Exercise movement, combat effects, hotkeys, accented text, inventory, context menus and every necessary auxiliary dialog. At 75%, 100%, 150% browser scale and after client resize, click recorded corner/center targets and confirm actual application results. Reject stale geometry and unsupported surfaces; never close dialogs to pass the test.
4. Delay A capture for four seconds; throttle A's frame receiver; disconnect A mid-key and mid-drag. Keep B continuously walking/clicking. Reconnect A twice and send recorded old commands through the first connection. Verify key release, same live process, and only the newest controller being effective. Destroy/recreate A's window and process; old bindings must fail, while B continues.
5. With the same two PXG processes and scene, measure no adapter/viewers, adapter only, capture only, and two viewers. Record CPU time deltas, private bytes, working set, per-PID GPU counters, transmitted bytes, browser CPU/memory/decode time and timestamped recordings. Use idle, walking, effects and menus. Distinguish input ACK, first changed encoded frame, browser presentation and input-to-photon timing. A five-second synthetic sample cannot establish a PXG performance budget.

For each case record pass/fail/not-executed, exact commands, identifiers, timestamps and artifacts. Stop affected functionality on input or capture failure. Never fall back to desktop capture, global input, shared keyboard state, clipboard or host filesystem access.
